|`rbac-backend` |`deploy/permission/Dockerfile.backend` |18081 业务、18082 健康（只在网络内） |`SPRING_PROFILES_ACTIVE=swarm`；logback 写控制台和 `/app/logs`；CORS 只放行课程前端的源地址
|`course-mgt-frontend` |老师仓库 `web/Dockerfile`，我们编译 |host 模式发布 80 |老师的 Nginx 配置：`/api/` 转发到 `course-mgt-backend:8080`
|`course-mgt-backend` |老师发布的镜像 |8080 业务、8081 健康（只在网络内） |`APP_IDENTITY_BASE_URL=http://rbac-backend:18081/api/apps/course-project-management`；登录服务所在的两个包日志为 INFO
|===

几点说明：

* 两个 stack 都接入集群已有的外部 overlay 网络 `javaee-proxy`，与 `lab`、`lab4` 共用。Swarm 给每个服务加上与服务名相同的网络别名，所以课程后端用 `rbac-backend` 访问权限系统，两个后端都用 `mysql` 访问 `lab_mysql`。
* 课程前端在浏览器里直接调用统一身份的 `/auth/permissions`、`/auth/departments` 等接口。地址在构建课程前端时写入 `VITE_IDENTITY_BASE_URL=http://120.46.213.158/api/apps/course-project-management`，所以权限系统的公网地址变了，要重新构建课程前端。
* 两个前端都用 host 模式发布 80 端口，原因有两个：
** 华为云安全组只放行 80、443、8080；
** ingress 的 8080 已被 `lab_productdemoaop` 占用，而 ingress 模式会让所有节点的同一端口都被占用。
+
host 模式只占用服务所在节点的端口，两个系统因此各用一台节点的 80 端口。
* 老师 stack 里的 Prometheus 没有部署：集群已有 `lab_prometheus`（网络别名同为 `prometheus`），节点内存也不够。
* 老师的登录服务在 DEBUG 级别把整个登录结果（含访问令牌）写进日志。课程 stack 用 `BACKEND_LOG_LEVEL_LOGIN=INFO` 把 `cn.edu.xmu.projectmgt.service.ddd.application.auth`、`cn.edu.xmu.projectmgt.service.structured.auth` 两个包调到 INFO，不改老师代码；其余各层仍是 DEBUG，分层切面的“开始/完成”日志和课程后端调用统一身份的外部请求日志照常输出。
* 每台节点只有约 1.8 GB 内存，所以两个后端放在不同节点，都设了内存上限，更新顺序为先停后启。部署后 CDWY3、CDWY4 各剩约 900 MB 可用内存。

== 准备

* 集群节点为 x86_64。权限系统与课程前端 Dockerfile 的基础镜像（SWR `oomall-javaee` 的 `openjdk:21-alpine`、`nginx:stable-alpine`）只有 amd64 版本，所以这些镜像直接在服务所在节点上构建，不需要镜像仓库。
* 课程后端用老师发布在 SWR `oomall-javaee` 的公开镜像，在 CDWY4 上直接 `docker pull`，不需要登录。
* 构建机需要 JDK 21、Maven、Node 22.22.2 或 24.15+。权限系统依赖 CloneFactory 0.0.2，先执行 `mvn -f third-party/clonefactory/pom.xml install`。

docker node update --label-add cdwy.course=true hcss-ecs-1488   # CDWY4

== 数据库

在本机经 ssh 发到 MySQL 所在的 CDWY2 执行，借用 `lab_mysql` 容器自带的 root 环境变量，命令里不出现 root 密码；SQL 从标准输入传入：

[source,bash]
----
MYSQL='docker exec -i $(docker ps -q --filter name=lab_mysql | head -1) sh -c "MYSQL_PWD=\"\$MYSQL_ROOT_PASSWORD\" mysql -uroot'
echo "CREATE DATABASE cdwy_rbac CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE DATABASE course_project CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;" | ssh root@<CDWY2> "$MYSQL\""
ssh root@<CDWY2> "$MYSQL cdwy_rbac\"" < docs/first-review/database-mysql.sql
ssh root@<CDWY2> "$MYSQL course_project\"" < ../course-project-mgt/deploy/coursemgt-2026_11_19_08_54_02-dump.sql
----

* 权限系统的表由 link:../first-review/database-mysql.sql[database-mysql.sql] 创建，应用以 `ddl-auto=validate` 启动。
* 课程库导入老师仓库 `deploy/` 下的 dump，其中已含 Flyway 迁移记录。

两个应用账号各自只能访问本库：

[cols="2,4",options="header"]
|===
|账号 |权限
|`cdwy_rbac`@`%` |`cdwy_rbac` 库的 SELECT、INSERT、UPDATE、DELETE
|`course_project`@`%` |`course_project` 库的全部权限（Flyway 迁移需要）
|===

`lab_mysql` 由多个实验共用（上限 300 个连接），两个应用的连接池都限制为 5。

== Docker secret

账号密码、JWT 密钥和管理员初始密码都在本机随机生成，经标准输入同时写入 MySQL 与 docker secret，不写文件、不进命令行参数：

[source,bash]
----
pw=$(openssl rand -base64 24 | tr -d '\n=/+')
printf '%s' "$pw" | ssh root@<管理节点> 'docker secret create cdwy_rbac_db_password_v1 -'
printf "CREATE USER 'cdwy_rbac'@'%%' IDENTIFIED BY '%s';\nGRANT SELECT, INSERT, UPDATE, DELETE ON cdwy_rbac.* TO 'cdwy_rbac'@'%%';\n" "$pw" \
  | ssh root@<CDWY2> "$MYSQL\""
unset pw
----

课程系统账号同理（`course_project`，授予本库全部权限）。JWT 密钥只写入 secret；管理员初始密码写入 secret，同时交给管理员本人保管。

[cols="3,3,4",options="header"]
|===
|secret |挂载为 |说明
|`cdwy_rbac_db_password_v1` |`spring.datasource.password` |权限系统数据库账号密码
|`cdwy_rbac_jwt_secret_v1` |`permission.jwt.secret` |JWT 签名密钥（64 个字符）
|`cdwy_rbac_bootstrap_password_v1` |`permission.bootstrap.password` |首次启动创建的管理员 `admin` 的密码；之后重复启动不会改动
|`course_project_db_password_v1` |`spring.datasource.password` |课程系统数据库账号密码
|===

* secret 以文件挂载到容器的 `/run/secrets/<属性名>`，两个后端都通过 Spring `configtree` 读取，不出现在环境变量和 `docker inspect` 里。
* 老师原来的 stack 用 `DB_PASSWORD` 环境变量传密码，这里改成了 secret。
* secret 的内容不能修改。要换密码时，新建 `_v2`，再用 stack 的 `*_SECRET` 变量指向它。

== 部署

在管理节点 CDWY1 上，把 link:../../deploy/stack.yml[deploy/stack.yml] 和 link:../../deploy/course/stack.yml[deploy/course/stack.yml] 分别放到 `/root/ooad-deploy/rbac`、`/root/ooad-deploy/course`。再按 link:../../deploy/.env.example[.env.example]、link:../../deploy/course/env.example[env.example] 写好各自的 `.env`：只有镜像名、端口和地址，没有密码。先部署权限系统：

[source,bash]
----
cd /root/ooad-deploy/rbac   && (set -a; . ./.env; set +a; docker stack deploy --resolve-image never -c stack.yml cdwy)
cd /root/ooad-deploy/course && (set -a; . ./.env; set +a; docker stack deploy --resolve-image never -c stack.yml course-project)
docker stack services cdwy; docker stack services course-project
----

* 镜像只存在于构建或拉取它的节点上，`--resolve-image never` 让 Swarm 直接使用节点上的本地镜像。课程后端在 `.env` 中按摘要引用老师的镜像，老师用同一标签重新推送时不会悄悄换版本；要跟进老师的新版本，在 CDWY4 上重新 `docker pull` 并更新 `.env` 中的摘要。
* 切换设计路线：改 `RBAC_BACKEND_STRATEGY` 或 `BACKEND_STRATEGY`（`structured` / `ddd`）后，重新执行同一条 `docker stack deploy`。
* 回滚：`docker service rollback <服务名>`。

== 常见问题

* 课程前端返回 502：查看 `docker service ps course-project_course-mgt-backend` 和 `docker service logs course-project_course-mgt-backend`，检查 MySQL 连接与 Flyway。
* 课程系统提示“统一身份认证暂时不可用”：课程后端访问不到 `rbac-backend:18081`。检查两个服务是否都在 `javaee-proxy` 网络上，`IDENTITY_BASE_URL` 是否以 `/api/apps/course-project-management` 结尾。
* 课程系统进入管理页面时提示无权限或权限校验不可用：多半是浏览器跨域被拒。确认 `RBAC_CORS_ALLOWED_ORIGINS` 与课程前端的地址完全一致（协议、主机、端口）；确认构建课程前端时的 `VITE_IDENTITY_BASE_URL` 正确。
* 课程系统删除教师是软删除，删过的工号不能再添加，会提示“这位教师已经存在”。这是老师系统的既有行为。
* 日志时间是 UTC，比北京时间晚 8 小时。
