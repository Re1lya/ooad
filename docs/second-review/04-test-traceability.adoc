== 执行方式与结果

测试连接真实 MySQL（8.0.16 及以上）。先准备一个空库和有建表、删表权限的账号，再用环境变量告诉测试连哪里：

[source,bash]
----
export TEST_DB_HOST=127.0.0.1 TEST_DB_PORT=3306 TEST_DB_NAME=rbac_test TEST_DB_USERNAME=rbac_test
export TEST_DB_PASSWORD=<测试账号密码>
mvn -B -f third-party/clonefactory/pom.xml install -Dmaven.test.skip=true
mvn -B clean verify          # 同时生成 target/site/jacoco/index.html
python3 scripts/build-test-traceability.py   # 按测试源码重新生成本文第 3 节的三张表
----

2026-11-21 结果（本机 MySQL 8.4）：186 个测试，失败 0、错误 0、跳过 0。JaCoCo：指令 93.6%、分支 84.0%、行 94.0%、方法 92.0%（含 CloneFactory 生成代码）。

== 测试约定

按课程代码规范的测试要求组织，与老师课程项目的测试写法一致：

[cols="2,5",options="header"]
|===
|约定 |本项目做法
|真实 MySQL，不 mock 数据库 |`src/test/resources/application-test.properties` 连接 MySQL；每个 Spring 上下文启动时先删表，再执行部署用的 `docs/first-review/database-mysql.sql`，Hibernate 以 `validate` 启动。`MySqlSchemaTests` 另外核对 validate 不检查的主键、唯一约束、外键与检查约束。
|测试事务回滚 |测试类标注 `@Transactional`，测试方法结束即回滚。清表用 `DELETE`（MySQL 的 `TRUNCATE` 会隐式提交）。`RequestTransactionBoundary` 用 JDBC 保存点模拟“一个请求一个事务”：请求前把改动写入数据库并清空持久化上下文；请求成功则写入，请求以异常结束则回滚到保存点。
|例外：并发测试 |`PhaseTwoRbac1Tests.FR18_concurrentOppositeEdgesCannotFormCycle` 的两个并发请求运行在各自的连接上，只能看到已提交的数据，所以这个测试标注 `Propagation.NOT_SUPPORTED`，结束时自行清空提交的数据。
|需求编号 |测试方法名以需求编号开头（如 `FR18_…`），`@DisplayName` 写明需求编号与验收条件。
|URL 常量 |URL 模板集中在测试类顶部的 `private static final String`，路径参数用 `{name}` 占位，由 `TestUrls.url(...)` 展开。
|错误码契约 |每个业务错误码至少有一个测试断言响应体的 `code`（见 3.3）。`ErrorCodeContractTests` 按需求逐个覆盖各模块的错误码。
|不存在的 id |`ErrorCodeContractTests.NFR07_everyByIdEndpointRejectsMissingIds` 覆盖全部 40 个按 id 操作的请求组合：两个 id 的接口分别让第一个、第二个 id 不存在，断言 404 和对应的 `*_NOT_FOUND`。
|共享契约 |`Ddd*` 测试类继承结构化测试类，两条设计路线运行同一组测试方法和数据，不复制断言。
|===
