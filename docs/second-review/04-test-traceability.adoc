== 执行方式与结果

测试连接真实 MySQL（8.0.16 及以上）。先准备一个空库和有建表、删表权限的账号，再用环境变量告诉测试连哪里：

[source,bash]
----
export TEST_DB_HOST=127.0.0.1 TEST_DB_PORT=3306 TEST_DB_NAME=rbac_test TEST_DB_USERNAME=rbac_test
export TEST_DB_PASSWORD=<测试账号密码>
mvn -B -f third-party/clonefactory/pom.xml install -Dmaven.test.skip=true
mvn -B clean verify          # 同时生成 target/site/jacoco/index.html
python3 scripts/build-test-traceability.py   # 按测试源码重新生成本文第 3 节的三张表
----

2026-11-24 结果（本机 MySQL 8.4）：315 个测试，失败 0、错误 0、跳过 0。JaCoCo：指令 97.8%、分支 89.1%、行 98.2%、方法 97.2%（含 CloneFactory 生成代码）。这次运行的完整报告存档在 link:evidence/jacoco/index.html[evidence/jacoco/index.html]，可逐个包、类查看每一行的覆盖情况。

|约定 |本项目做法

|等价类、边界值、异常 |每条功能需求都有这三类测试，用 JUnit `@Tag("等价类")`、`@Tag("边界值")`、`@Tag("异常")` 标注（浏览器测试在 `test(...)` 上一行注明）。边界值在界限两侧各取一个值，例如登录名 128 个字符按账号校验、129 个字符返回 400，分页 `pageSize` 取 1、100 与 0、101。`ConsoleRequirementTests` 与 `DddConsoleRequirementTests` 集中补充控制台需求的三类用例。生成脚本发现某条功能需求缺少任一类时直接报错（见 3.2）。可以按类型单独运行，例如 `mvn test -Dgroups=边界值`。
|URL 常量 |URL 模板集中在测试类顶部的 `private static final String`，路径参数用 `{name}` 占位，由 `TestUrls.url(...)` 展开。
|错误码契约 |每个业务错误码至少有一个测试断言响应体的 `code`（见 3.3）。`ErrorCodeContractTests` 按需求逐个覆盖各模块的错误码。
|不存在的 id |`ErrorCodeContractTests.NFR07_everyByIdEndpointRejectsMissingIds` 覆盖全部 40 个按 id 操作的请求组合：两个 id 的接口分别让第一个、第二个 id 不存在，断言 404 和对应的 `*_NOT_FOUND`。
|共享契约 |`Ddd*` 测试类继承结构化测试类，两条设计路线运行同一组测试方法和数据，不复制断言。
